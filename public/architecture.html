Flow of Control

  1. 1. Client / Browser (Tailwind UI): HTML5 and JavaScript trigger async fetch() requests with JSON payloads.
  2. 2. Controller Layer (@RestController): Receives HTTP requests, validates DTOs (@Valid), and invokes the service layer.
  3. 3. Service Layer (@Service): Handles business logic, transactions (@Transactional), and BCrypt hashing.
  4. 4. Repository Layer (@Repository): Extends JpaRepository for CRUD operations, pagination, and JPQL queries.
  5. 5. Database Layer (MySQL): Persists user records, movie catalog metadata, and favourite associations.

GET /api/movies Get all movies (supports ?title, ?genre, ?sort) 200 OK

GET /api/favourites/{userId} Get user's favourited movie list 200 OK
POST /api/favourites Add movie to user's favourites 200 OK / 409

MySQL DDL Tables

CREATE TABLE IF NOT EXISTS users ( id BIGINT AUTO_INCREMENT PRIMARY KEY, name VARCHAR(100) NOT NULL, email VARCHAR(150) NOT NULL UNIQUE, password VARCHAR(255) NOT NULL, created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ) ENGINE=InnoDB; CREATE TABLE IF NOT EXISTS movies ( id BIGINT AUTO_INCREMENT PRIMARY KEY, title VARCHAR(255) NOT NULL, description TEXT, genre VARCHAR(100), rating DOUBLE, duration VARCHAR(50), release_date VARCHAR(50), director VARCHAR(150), starring_cast TEXT, language VARCHAR(100), country VARCHAR(100), poster_url VARCHAR(500), backdrop_url VARCHAR(500), trailer_url VARCHAR(500), is_trending BOOLEAN DEFAULT FALSE ) ENGINE=InnoDB; CREATE TABLE IF NOT EXISTS favourites ( id BIGINT AUTO_INCREMENT PRIMARY KEY, user_id BIGINT NOT NULL, movie_id BIGINT NOT NULL, created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP, CONSTRAINT fk_fav_user FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE, CONSTRAINT fk_fav_movie FOREIGN KEY (movie_id) REFERENCES movies(id) ON DELETE CASCADE, CONSTRAINT uq_user_movie UNIQUE (user_id, movie_id) ) ENGINE=InnoDB;

How do you handle password security in Spring Boot?

We use BCryptPasswordEncoder from Spring Security. Passwords are never stored in plain text. On registration, the password is salted and hashed before persistence, and during login, passwordEncoder.matches(raw, encoded) validates the hash.

How is data transferred between frontend and backend?

The frontend communicates asynchronously using the modern Fetch API with JSON payloads. The Spring Boot backend exposes REST endpoints annotated with @RestController, parsing JSON into typed Java DTOs using Jackson.
